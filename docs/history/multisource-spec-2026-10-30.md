# Paper Daily · 学术论文日报

公开网站：https://paperdaily.wfz521.com/

客观整理数学、计算机科学、网络与信息安全、密码学论文。**发布来源与研究领域是两个独立维度**。网页支持日期、来源、领域、细分主题、阅读深度和文本检索，以及按来源或领域分组。

## 内容原则

- 只使用公开学术资料，不包含个人研究进度、私人文件、内部笔记或“与我的研究相关”等评价。
- 给出中英文标题、全部作者、简短作者与署名机构介绍、研究问题、主要结果、方法、条件/局限、原文链接、版本与日期。
- 作者机构以该稿署名为准。机构/角色没有可靠来源时写未披露或待核实，不补猜职位、资历或声誉。
- 明确预印本、技术报告、正式发表。`reading_depth` 为 `abstract`（摘要/元数据）或 `partial`（部分正文）。局部阅读不是完整证明审核、性能复现或安全性背书。
- 摘要中的结果统一视为作者报告。重要结论说明模型、假设和适用范围，性能注明基线与硬件/参数核验范围。
- 来源访问失败、索引滞后、尚未确认新增分别记入 `coverage`。没有搜到不等于不存在；禁止声称已覆盖所有论文。

## 文件结构

- `index.html`、`assets/`：无外部依赖的静态页面。
- `data/sources.json`：持续跟踪的来源目录、范围与处理规则。
- `data/issues/YYYY-MM-DD.json`：每日独立数据。日期采用刚结束的 AOE（UTC−12）自然日；检索窗口保存 UTC。
- `data/issues.json`：日期归档索引与最新一期。
- `data/seen.json`：已收录的稳定论文身份和版本，供跨日去重。
- `reports/YYYY-MM-DD.md`：从审核后的 JSON 生成的中文 Markdown。
- `tools/render_markdown.py`：不联网的 Markdown 生成器。
- `tools/validate.py`：结构、日期、来源、重复项和编辑规则检查。

## 增量更新流程

1. 读取本说明、来源目录、最新一期覆盖记录和已收录索引；保留历史期刊记录与用户修改。
2. 按 AOE 窗口和每个来源上次**实际检索覆盖**读取原始公开公告/发表列表。初期未覆盖的来源不能虚构水位。每日查看 arXiv、ePrint、ECCC，并按官方来源的实际发布节奏检查期刊与会议。
3. arXiv 按稳定编号、ePrint 按年份/编号、正式出版按 DOI 去重；再核标题与作者，合并跨平台版本的来源链接。不同版本不是新论文，记录已核的增量；不能仅凭更新时间杜撰变化。
4. 客观筛选并写入论文字段。`first_date` 不等于公告或更新日期；保留版本证据与作者机构来源。核不到的内容明确标注，不以旧稿凑数。
5. 建立新 `data/issues/YYYY-MM-DD.json`，更新索引和 `seen.json`。当天重跑先核当前提交与当日文件，必要时增量更正，不生成重复条目。无可靠新结果也可发布零篇日报及实际检索范围。
6. 运行 `python3 tools/render_markdown.py`、`python3 tools/validate.py`、`node --check assets/app.js`。更新交互时检查桌面/手机布局、组合筛选、无结果、清除、日期切换和网络失败。
7. 将日报、结构化数据和必要来源说明保存 Space 的 **学术论文日报** 目录，保留历史。公共发布内容应与 Space 存档一致。
8. 提交到 `wang2000star/paper-daily` 的 main，采用当前分支头进行非强制更新；保留 `CNAME` 和其他无关文件，不改 DNS、凭据或仓库安全设置。
9. 核验远端新提交及 GitHub Pages 实际提供的首页/数据版本。若失败，记录“已保存/已提交/已上线”各自状态，不能把提交成功等同上线。

## 日程与运行边界

日报由已设置的每日任务采集、整理、存档并提交；本站是 GitHub Pages 静态展示端，**没有在仓库中虚构一个自带联网摘要能力的后台服务**。后续运行不依赖查看者的电脑，也不在前端放置任何 API 密钥。具体运行状态以每日实际产物为准。

默认不发送邮件。网站不使用第三方分析/追踪脚本。未取得独立开源许可前，不推定本仓库赋予第三方超出版权法的代码或内容再许可；引用论文版权属于作者或出版方。

## AOE 日界规则（替代此前七天回看与北京时间日期规则）

- 每日 AOE 24:00 更新，即 UTC 次日 12:00、北京时间次日 20:00；固定 UTC−12，无夏令时。
- 截止时刻为 T 时，仅收录 [T−24h,T) 内首次公开发表/公告的论文；归档日期是刚结束的 AOE 自然日。首份为 AOE 2026-10-29，计划北京时间 2026-10-30 20:00 发布，UTC 窗口 2026-10-29 12:00 至 2026-10-30 12:00。
- 区分投稿/收稿时间、首次公开公告时间、修订时间、正式出版时间。arXiv 采用公开公告证据，不把提交日期自动当公开时间；ePrint 需确认公开发布证据，不能仅用 First received 替代。
- 每篇保存 public_at、public_time_source、public_time_precision 与 eligibility。只有可靠时间证据可确认落入窗口时标 confirmed；日期时区未知或时间区间跨越边界者标 pending，单列“时间待核实”，不得计入已确认新论文总数。
- 旧稿修订不算新发表。已在预印本出现的正式发表记录仅作为出版状态更新，关联同一工作，不重复当新论文。
- 不发布未结束窗口的完整日报，不再进行七天回看。迟到索引应注明实际公开日期，并作为补录而不是当日新稿。
- data/issues.json 的 issues/latest 仅包含正式 AOE 日报；historical_trials 保留旧试刊，排除日统计。旧文件不删除，试刊去重索引不阻止符合首个正式窗口的论文被正常收录。

## 机构网页与研究代码同样是原始来源

来源目录纳入 OpenAI、Anthropic、Google DeepMind、Microsoft Research 官方研究页面及已核的官方 GitHub 组织入口；并非只检索预印本/期刊。目录不是当日已完成覆盖声明。机构、大学实验室或作者官方页面亦可在身份核验后加入。

- 每条 content_type 明确为 paper、research_blog、technical_report、research_code 或 model_release；这些类型不是同行评审状态。
- 只收具体研究成果及方法/实验/理论/代码/模型技术材料，不收纯营销、融资、产品公告或仅因热门而入选的仓库。
- repo created_at、commit authored/committed 时间不自动等于研究首次公开时间；需官方发布公告、release 或可追溯公开证据。时间不明确列 pending。
- 同一研究的博客、报告、arXiv 和 GitHub 聚合到同一 work_id，保留多条来源，不重复计数。作者机构及阅读深度规则不变；没有个人作者署名时如实写机构团队，不能编造成员。

历史试刊的稳定归档在 `data/trials/` 与 `reports/trials/`，避免与未来同名 AOE 日期冲突；原始旧路径暂留兼容，不作为正式索引。

## 正式日报的资料准入门槛（最新规则）

- 优先获取并阅读全文；最低须取得可靠原始来源的标题及完整摘要，且确实阅读。仅标题、搜索片段或无法查看摘要的条目不收录。
- 摘要级 reading_depth=abstract，显著标明“摘要级解读”。必须提供 abstract_review：source_url（原始完整摘要URL）、complete_abstract_accessed=true、read_confirmed=true、scope（实际阅读范围）。这些标记必须有真实访问与阅读依据，不得为通过验证而虚填。
- 摘要不能支持的方法细节、参数、安全性或证明步骤写“摘要未披露/未核实”，不推测，不把作者主张当独立验证。
- partial/full_review 须提供 substantive_review：content_urls、scope、method_evidence、result_evidence、conditions_evidence，说明实际阅读位置、内容与未覆盖范围。局部阅读不等于完整证明审计或实验复现。
- 研究博客、技术报告、代码发布若没有规范摘要，可用原始页面实质研究概述代替，abstract_review.overview_kind 标 research_overview，说明来源类型与实际范围；营销描述不算研究概述。
- 可使用合法官方同版本全文或完整摘要替代入口，记录URL和版本对应。无法达到最低标题+完整摘要/实质概述门槛者仅记入检索日志，不在日报占条目。
- 历史试刊仍独立归档，不自动视为符合新准入门槛。作者机构、客观表述、AOE日界和跨来源去重规则不变。

## 网页阅读交互

- 默认以折叠卡片展示中英文标题、来源/阅读深度标签及简短概览。概览直接取已保存的 overview、主要结果或研究问题；超过 150 字符截断，不生成新论文结论。
- 点击标题或“展开总结”在当前卡片展开完整现有总结；再次点击收起。支持键盘 Tab、Enter 和空格，使用 aria-expanded/aria-controls 与隐藏区域标明状态。
- 展开区保留研究问题、主要结果、方法、条件与局限、作者机构、日期/版本及实际阅读范围；“原始论文”保持为单独来源链接。展开总结不代表已阅读全文。
- 同一期中筛选、清除筛选或改分组不会丢失已展开状态；成功切换日期后重置为折叠。试刊不进入正式索引，不能为测试交互而给旧数据补造阅读证据。
- 回归检查：`node tools/test_ui.cjs`（无外部依赖）。浏览器还须检查标题/按钮重复开关、键盘、筛选后状态及手机换行；使用隔离的测试页，不改正式数据。

## 正式日报的时间证据与阅读范围展示

- `papers` 仅放 `eligibility=confirmed` 且最低阅读证据齐备的新增；`pending_papers` 仅放已读完整摘要/实质内容、但公开时间边界待核实的条目。待核实单列，不计入确认新增；筛选和原有展开总结交互同样适用。
- 保存 `public_at`、`public_time_source`（原始时间证据 URL）、`public_time_precision` 和 `date_note`。不得把仅日期或未知时区转换成伪造的精确午夜时间。
- 确认项须有窗口内的带时区精确时间，或原始证据支持的 `public_time_range={start,end}` 且整个区间落在窗口内。日期/时区不能排除跨界的条目只能 pending；提交、收稿、仓库 commit 时间不能冒充首次公开。
- `editorial_note` 在网页顶部与 Markdown 显著说明本期为选择性/部分阅读覆盖，区分发现条数、实际阅读条数、确认新增和时间待核实。目录发现不等于完成逐篇摘要阅读，更不等于全文审读。
- `retrieval_log` 指向当日详细检索 JSON，记录所有目录来源的实际入口、覆盖范围、失败/未查、发现与阅读计数及排除原因。未读标题、摘要不可得和访问失败只在检索档案，不进入论文卡片。
- 新的正式日报 Markdown 仅由正式索引生成，不重写历史试刊。检验命令：`python3 tools/render_markdown.py && python3 tools/validate.py && python3 tools/test_time_validation.py && node --check assets/app.js && node tools/test_ui.cjs`。

## 多渠道发现与发布来源分离

- 每日实际检索 PubScholar、OpenAlex、Semantic Scholar，并以其为发现、交叉核对及原文入口定位工具；不得仅把名字加进目录就宣称完成覆盖。`data/sources.json` 的 `discovery_indexes` 与发布方 `sources` 分列，已有 DBLP 也标为辅助索引；Crossref 用于 DOI 和出版商存缴元数据核对。
- 每条研究的 `source` 仍是核实后的真实发布平台/期刊/会议/机构；可另存 `discovered_via=[{index_id,record_url,accessed_at}]`。通过 OpenAlex 找到的 arXiv 论文仍属于 arXiv，不得靠改标签制造“多来源”。
- 检索后回溯原始摘要/全文及发表证据，检查 DOI、稳定论文编号、作者、题目和版本关系。索引 created/updated/indexed 时间不等于论文首发；出版日期仅到日、时区未知或存在更早版本时，按既有规则待核实或作为出版状态更新，不冒充新增。
- 非 arXiv 来源须继续做实际检索，不用少数入口的失败代替研究。每个渠道记录查询、入口、时间范围、分页完成度、发现/阅读/入选数量和访问缺口；未读标题与失败入口留在检索日志，不进入主页面论文卡片。
- 网页来源数只统计确认新增的真实发布来源，另列“仅待核实来源”；下拉框及来源快捷筛选展示整期确认/待核实数量。这个展示修正不改变论文内容，也不等于已经扩展阅读覆盖。
- 当前官方参考：[PubScholar 发布说明](https://www.cas.cn/yw/202311/t20231101_4983866.shtml)、[OpenAlex 帮助](https://help.openalex.org/)、[Semantic Scholar Academic Graph 文档](https://api.semanticscholar.org/api-docs/graphs)。

- 正式发表事件候选可先列 `pending_papers`，明确已有预印本或作者稿，不计新研究首发；后续即使核实发表时间，也应按同一工作关联出版状态，不自动重复加入新增。补录在 `amendments` 保留修改时间、实际新增/待核实数量和旧检索证据。
